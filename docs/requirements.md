# Tether 管理服务器（hub）需求文档

> 组件：`tether-hub`，自托管管理服务器（第二阶段，**尚未开始**，以下需求状态均为“计划中”）
> 相关文档：[前端 GUI](https://github.com/tongxin-77/tether/blob/main/docs/frontend-requirements.md) · [后台服务 daemon](https://github.com/tongxin-77/tether/blob/main/docs/daemon-requirements.md) · [索引](https://github.com/tongxin-77/tether/blob/main/docs/README.md)

## 1. 背景与目标

用户在多台 Windows 机器上运行 Tether，每台机器的 `tetherd` 各自持有会话。hub 让用户在一个网页里看到所有机器的会话，并在需要时远程接管某个会话（例如离开电脑后在别处继续操作 Claude Code）。

目标：

- 汇总所有机器的会话列表与状态（含 Claude 状态），轻量、实时。
- 按需远程接管单个会话：看到当前画面并可输入。
- 客户端零入站端口：由 daemon 主动出站连接 hub。
- 仅个人使用，部署和运维尽量简单。

## 2. 范围 / 非目标

**范围**：hub 服务端（Node.js + TypeScript）、Web 界面（机器 / 会话列表 + xterm.js 会话视图）、daemon ↔ hub 协议、token 认证、接管审计。

**非目标**：

- 不支持多用户 / 团队 / 权限体系；单用户。
- 不提供 SaaS；仅自托管。
- 默认不传输、不存储终端内容；不做会话录像。
- 不通过 hub 创建 / 关闭会话、不做文件传输（首版）。
- 不替代本地 GUI；hub 不可用时本地功能不受任何影响。

## 3. 功能需求

### 3.1 机器接入

| 编号 | 需求 | 验收标准 | 状态 |
|------|------|----------|------|
| H-1.1 | daemon 主动以 WSS 连接 hub，携带 token；hub 地址与 token 在 Tether 设置中配置 | 客户端不开放任何入站端口即可在 hub 看到该机器 | 计划中 |
| H-1.2 | hub 识别机器（机器名 + 稳定机器 ID），显示在线 / 离线与最后在线时间 | 断网后机器显示离线，恢复后自动上线 | 计划中 |
| H-1.3 | daemon 断线自动重连（指数退避），hub 重启后无需人工干预 | 重启 hub，所有客户端在退避周期内恢复 | 计划中 |
| H-1.4 | 客户端可脱离 hub 单独使用：hub 为可选功能，默认关闭；未配置、未启用、连接失败或 hub 宕机时，本地全部功能照常可用，不弹阻断性提示 | 不配置 hub 安装使用，功能与现在一致；运行中关停 hub，本地会话、SSH、文件树等不受影响 | 计划中 |
| H-1.5 | 客户端设置新增「管理服务器」分组：启用开关、服务器地址（IP 或域名 + 端口）、token；提供「测试连接」按钮，并显示当前连接状态（未启用 / 连接中 / 已连接 / 失败原因） | 在设置中填写地址并测试，可得到明确的成功或失败原因；关闭开关后 daemon 断开 hub 连接 | 计划中 |

### 3.2 会话汇总

| 编号 | 需求 | 验收标准 | 状态 |
|------|------|----------|------|
| H-2.1 | daemon 上报会话列表与元信息：名称、cwd、主机（远程会话）、状态、Claude 状态、最后活动时间；变化时推送 | hub 列表与本地 GUI 侧栏一致，延迟秒级 | 计划中 |
| H-2.2 | 默认不上传终端内容，流量与会话变化次数相关而非输出量 | 会话大量输出时 hub 链路流量不随之增长 | 计划中 |
| H-2.3 | Web 页面按机器分组列出会话，突出“等待确认”等需要关注的会话 | 一眼可见哪台机器的哪个 Claude 在等确认 | 计划中 |

### 3.3 远程接管

| 编号 | 需求 | 验收标准 | 状态 |
|------|------|----------|------|
| H-3.1 | 用户在 hub 点击接管某会话后，daemon 才开始发送：先 vt100 屏幕快照，再实时输出 | 接管前链路无终端内容；接管后画面与本地一致 | 计划中 |
| H-3.2 | 接管期间 hub 可发送输入与 resize | 在网页中可正常操作 shell / Claude Code | 计划中 |
| H-3.3 | 本地 GUI 显示“被接管中”标识，并可一键收回控制；收回后 hub 停止输入（只读或断开，待定） | 本地收回后 hub 输入无效 | 计划中 |
| H-3.4 | 本地设置可禁止接管：按机器（必需）；按会话（待定） | 关闭开关后接管请求被拒绝，hub 显示原因 | 计划中 |
| H-3.5 | 结束接管（用户关闭视图或断线）后 daemon 停止推送内容 | 关闭网页标签后链路回到仅元信息 | 计划中 |
| H-3.6 | Web 会话视图使用 xterm.js，复制粘贴行为尽量与本地一致 | 颜色正确、可粘贴多行 | 计划中 |

### 3.4 审计

| 编号 | 需求 | 验收标准 | 状态 |
|------|------|----------|------|
| H-4.1 | 记录接管事件：时间、机器、会话、来源 IP、开始 / 结束 / 被本地收回 | 每次接管在审计日志可查 | 计划中 |

## 4. 接口：daemon ↔ hub

- 方向：daemon → hub 出站 WebSocket over TLS（WSS），长连接 + 心跳。
- 认证：连接时携带 token；hub 校验失败直接断开。
- 消息（JSON，沿用管道协议风格，`type` 区分）：
  - 上行：机器注册（机器 ID、名称、Tether 版本）、会话全量 / 增量（复用 `proto::SessionInfo`）、接管期间的快照与输出（base64）。
  - 下行：开始接管 / 结束接管、输入、resize。
- 本地 GUI 侧需要的新消息（被接管状态、收回控制、禁止接管设置）在 daemon 管道协议中扩展，见 [daemon §3.7](https://github.com/tongxin-77/tether/blob/main/docs/daemon-requirements.md#37-hub-客户端第二阶段) 与 [前端 §5](https://github.com/tongxin-77/tether/blob/main/docs/frontend-requirements.md#5-接口)。
- 需要协议版本字段，允许 daemon 与 hub 独立升级。

## 5. 非功能需求

### 5.1 性能与资源

- hub 面向个人规模（约 10 台机器、每台数十会话以内），单进程即可。
- 客户端侧：未接管时 hub 连接对 daemon 的内存 / CPU 增量应可忽略（目标：空闲 CPU 仍为 0%，内存增量 MB 级以内）。

### 5.2 安全

- **TLS 必需**：只接受 WSS / HTTPS，禁止明文 ws / http（本机调试除外，需显式开关）。
- **token**：客户端 token 存 Windows 凭据管理器，不写 config.json；支持轮换（hub 签发新 token、吊销旧 token），不同机器使用不同 token 以便单独吊销。
- **Web 界面认证**：访问 hub 页面需单独登录（方式待定），与机器 token 分离。
- **客户端无入站端口**：所有连接由 daemon 发起。
- **接管默认需本地允许**：按机器开关，可完全禁止。
- **暴露面**：需明确仅局域网 / VPN 还是公网部署；公网部署时的额外防护（限流、失败锁定）见待定项。
- 审计日志记录所有接管。

### 5.3 兼容性

- 服务端：Node.js LTS + TypeScript。
- 浏览器：现代桌面浏览器（Chromium / Firefox / Safari 新版）；移动端可用性待定。
- 客户端：随 Tether 版本发布；hub 不可用或未配置时 daemon 行为与现在完全一致。

## 6. 待定项

1. 部署形态：Docker 镜像 / 单可执行文件 / 直接 `node` 运行。
2. 持久化：无持久化（纯内存，重启后靠客户端重报）vs SQLite（保存机器、token、审计日志）。审计与 token 吊销倾向需要持久化。
3. 多设备同时观看同一会话：是否允许、只读旁观与输入权如何分配。
4. 通过 hub 推送通知（如 Claude 等待确认时推到手机 / 浏览器）。
5. 按会话禁止接管是否需要。
6. 本地收回控制后 hub 侧是只读继续观看还是直接断开。
7. Web 界面认证方式（密码 / TOTP / 反向代理认证）。
8. 公网部署的安全基线（限流、失败锁定、IP 白名单）。
9. 是否需要端到端加密（hub 自托管，当前假设 hub 可信）。
